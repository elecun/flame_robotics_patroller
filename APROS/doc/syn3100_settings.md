# SYN-3100 + TOP901 듀얼 안테나 설정 가이드

이 문서는 SYN-3100(UM982 듀얼 안테나 수신기)에 TOPGNSS TOP901 안테나 두 개를 연결해 위치와 차량 헤딩을 얻는 설치·설정 절차를 정리한다. SYN-3100은 듀얼 안테나 헤딩을 지원하며 TOP901은 GPS L1/L2/L5 등 다중 GNSS 대역을 지원하는 능동 안테나다. 실제 설치 전에는 보유한 SYN-3100 하드웨어 리비전의 라벨과 동봉 케이블을 기준으로 커넥터, 공급 전압, UART 매핑을 확인한다.

## 1. 구성품과 신호 흐름

- SYN-3100 수신기: UM982, GNSS ANT1/ANT2 입력, GPS I/O(micro-USB), USB-C 및 UART/CAN 인터페이스
- TOP901 안테나 2개: 각 안테나의 SMA-J 단자에서 SYN-3100의 GNSS ANT1/ANT2로 연결
- GNSS 보정 데이터: RTCM v3.x를 네트워크 또는 기준국에서 수신기에 전달해야 RTK 고정해(FIX)를 얻을 수 있음
- 수신기 출력: 듀얼 안테나의 GNSS 기준선으로 계산한 heading을 GPTHS 등의 문장으로 출력

SYN-3100은 위치·헤딩 수신기이고 TOP901 두 개는 각각 별도의 안테나 입력에 연결한다. RF 분배기를 사용해 안테나 하나를 두 포트에 나누어 연결하지 않는다.

## 2. 전원과 안테나 연결

### 전원

1. 전원을 끈 상태에서 동봉된 케이블을 사용해 SYN-3100의 전원 입력(제품에 표기된 USB-C 포트)을 안정된 전원에 연결한다.
2. 공급 전압과 전류 용량은 수신기 본체 라벨/동봉 전원 사양을 따른다. 공개된 제품 자료에는 SYN-3100의 입력 전압 범위가 기재되어 있지 않으므로 임의의 DC 전압을 전원선에 인가하지 않는다. USB-C 전원으로 공급하는 구성에서는 제조사가 지정한 전원 어댑터/케이블을 사용한다.
3. 본체 전원 표시등이 켜지는지 확인한다. GNSS 수신기 전원을 넣기 전에 두 안테나를 먼저 연결한다.

### 안테나

1. 본체의 `GNSS ANT1` 포트에 주 안테나(Master), `GNSS ANT2`에 보조 안테나(Slave)를 연결한다. 두 포트의 실제 표기는 본체 실크 인쇄를 따른다.
2. TOP901의 SMA-J와 수신기 포트 규격이 맞는지 확인하고, 필요하면 손실이 낮은 동축 케이블/정품 변환 케이블을 쓴다. 포트가 손상되지 않도록 커넥터를 비스듬히 물리거나 과도하게 조이지 않는다.
3. TOP901은 LNA 내장 능동 안테나로 사양상 동작 전압은 3.3–16 V DC, 소비 전류는 최대 45 mA다. 수신기 ANT 포트에서 안테나 바이어스 전원을 공급하는지 확인한다. 외부 바이어스를 추가할 때는 수신기 사양 확인 없이 전압을 중복 인가하지 않는다.
4. 안테나를 금속 지붕 위의 평평하고 단단한 브래킷에 고정하고, 두 안테나가 하늘을 향하게 한다. 차량 지붕 가장자리, 배기구, LTE 송신 안테나, 전원 변환기, 큰 금속 구조물은 피하고 두 안테나 주변의 시야를 가리지 않는다.
5. 기준선이 설치 중 움직이지 않도록 견고하게 고정한다. 기준선은 두 안테나의 위상중심 간 거리이며, 케이스 가장자리 간 거리가 아니다. 실측한 ANT1–ANT2 중심 간 거리를 기록한다.

## 3. 헤딩 기준선과 설치 방향

듀얼 안테나 헤딩은 주 안테나 ANT1에서 보조 안테나 ANT2로 향하는 기준선 벡터를 기준으로 계산된다. 차량 전방 헤딩을 바로 얻으려면 안테나를 전후 방향으로 배치하고 ANT1을 뒤쪽, ANT2를 앞쪽에 둔다. ANT1을 앞쪽에 두면 기준선 벡터가 차량 후방을 향하므로 출력이 차량 전방과 180° 차이 날 수 있다. 좌우 배치처럼 기준선과 차량 종축이 다르면 출력 헤딩에 장착 오프셋을 보정한다.

- ANT1/ANT2 포트 라벨과 실제 안테나 위치를 설치도에 표시한다.
- 가능하면 두 안테나를 전후 방향으로 설치하고, ANT1을 뒤쪽, ANT2를 앞쪽에 두며 베이스라인을 길게 확보한다. 기준선이 길수록 헤딩 정밀도에 유리하다. 단단한 고정과 수신기 권장 기준선 길이 범위를 함께 고려한다.
- 소프트웨어에서 `CONFIG HEADING LENGTH`를 설정할 때는 안테나 위상중심 사이 실측값을 cm 단위로 넣는다. 예: 중심 간격 80 cm, 허용오차 3 cm이면 `CONFIG HEADING LENGTH 80 3`.
- 안테나 기준선 방향과 차량 전방이 다르면 최종 헤딩을 차량 종축과 비교해 오프셋을 측정한다. `CONFIG HEADING OFFSET`은 헤딩/피치 출력에 보정값을 더하므로, 오프셋의 부호와 값은 해당 UM982 펌웨어 및 안테나 배치에서 시험해 확인한다. 임의로 90도를 입력하지 않는다.

수평이 맞고 GNSS 시야가 양호한 개활지에서 확인한다. 정지 상태에서도 듀얼 안테나 헤딩은 계산되므로, 주행 중 속도 기반 COG(course over ground)에 의존해 헤딩을 확인할 필요가 없다.

## 4. UM982 수신기 설정

### PC 연결

1. SYN-3100의 GPS I/O(micro-USB) 또는 USB-C 데이터 연결을 PC에 연결한다. 제품의 USB-C 포트 기능은 하드웨어 리비전에 따라 다를 수 있으므로 실제 연결 후 장치 관리자/`/dev/ttyACM*` 또는 `/dev/ttyUSB*`에서 GNSS 직렬 포트를 식별한다.
2. Unicore UPrecise 또는 호환 직렬 터미널을 열고, 확인한 포트와 수신기의 현재 baud rate를 지정한다. UM982 모듈 기본 baud를 가정하지 말고 포트 조회 후 사용한다. 8 data bits, no parity, 1 stop bit(8-N-1)로 연결한다.
3. 입력창에서 명령 응답을 확인할 수 있는지 `VERSION` 또는 `CONFIG` 같은 조회 명령을 보내 연결을 확인한다. USB 포트별로 명령 입력/출력 가능 여부가 다르면 제조사 문서의 포트 매핑을 따른다.

### 헤딩과 출력 문장

UM982 듀얼 안테나 모듈은 기본적으로 heading 계산이 활성화되어 있다. 설치 기준선을 고정해 사용하는 로봇에서는 다음 예시처럼 설정할 수 있다. 아래 `COMx`는 PC에서 연결한 포트가 수신기 내부에서 매핑되는 UM982 COM 포트로, 장치 구성에 맞춰 바꾼다.

```text
CONFIG HEADING FIXLENGTH
CONFIG HEADING LENGTH 80 3
GPTHS COMx 1
SAVECONFIG
```

위 예시는 ANT1–ANT2 기준선이 80 cm일 때다. `80`은 기준선 길이, `3`은 길이 허용오차이며 둘 다 cm다. 실제 중심 간 거리를 측정해 입력한다. 이동 중 기준선 길이가 일정하지 않은 설치라면 FIXLENGTH를 사용하지 말고, 설치에 맞는 VARIABLELENGTH 등 운용 모드를 제조사 문서에서 선택한다.

차량 전방 기준으로 헤딩 오프셋 보정이 필요한 경우에만 아래 항목을 설정하고 저장한다. 두 번째 인수는 피치 보정값이며, 수평 장착이면 보통 0부터 시작한다.

```text
CONFIG HEADING OFFSET <heading_offset_deg> 0
SAVECONFIG
```

명령 이름·출력 포트·지원 문장은 UM982 펌웨어 버전에 따라 달라질 수 있다. 응답이 `unrecognized`이거나 `GPTHS`가 출력되지 않으면 SYN-3100 공급사 문서/기술지원으로 해당 펌웨어의 UM982 명령 및 SYN-3100 COM 포트 매핑을 확인한다. 제품 설정을 초기화하는 `FRESET`은 사용하지 않는다.

### RTK 보정 데이터

헤딩 산출 자체는 두 안테나의 동시 GNSS 관측으로 이루어지지만, 센티미터급 위치를 얻으려면 유효한 RTCM v3.x 보정 스트림이 필요하다. 사용 중인 NTRIP/기준국 서비스의 접속 정보를 수신기 또는 연결된 호스트에 설정하고 RTCM이 수신기로 들어오는지 확인한다. SYN-3100 표시등에서 RTCM/RTK 상태를 보고, 가능하면 수신기 상태 로그로 correction age와 RTK 상태를 확인한다.

## 5. 헤딩값 검증

1. 안테나 기준선을 차량 진행 방향(ANT1 뒤, ANT2 앞)으로 설치하고 수신기를 켠다.
2. 개활지에서 두 안테나 모두 위성 추적 상태가 되는지 확인한다. 기준선 길이 추정값이 실측값과 일치하는지 확인한다.
3. 직렬 출력에서 `GPTHS` 또는 펌웨어가 제공하는 동등 heading 메시지를 확인한다. 헤딩은 도 단위, 진북 기준 시계방향(북 0°, 동 90°, 남 180°, 서 270°)인지 확인한다. GPTHS 상태 필드가 `V`(invalid)이면 숫자만 사용하지 않는다. UM982 예시 출력에서는 상태 필드가 `T`로 표시될 수 있다.
4. 차량을 북쪽, 동쪽, 남쪽, 서쪽으로 각각 향하게 해 나침반/GNSS 기준과 비교한다. 장착 오프셋이 일정하게 남으면 기준선 방향과 ANT1/ANT2 순서를 다시 확인한 후 오프셋을 보정한다.
5. 정지 시 헤딩과 천천히 회전할 때 헤딩이 연속적으로 변하는지 확인한다. 실측 기준선과 보고된 기준선 길이가 다르거나 헤딩이 약 180° 반대면 ANT1/ANT2가 뒤바뀌었을 가능성이 높다.

## 6. APROS 소프트웨어 연동

현재 저장소의 장치 설정은 [apros.cfg](../apros.cfg)의 `[synerex_syn3100]` 구간에 있다.

```ini
[synerex_syn3100]
port = /dev/ttyACM1
baudrate = 9600
update_interval_sec = 0.2
enable = false
```

수신기의 GNSS 출력용 USB 직렬 포트가 실제로 `/dev/ttyACM1`인지 확인한 후 `port`를 맞춘다. `baudrate`도 그 포트의 실제 설정과 일치시킨다. 예를 들어 UM982 COM 포트를 115200 baud로 설정했다면 APROS도 `baudrate = 115200`으로 맞춘다. 연결을 시작할 때만 `enable = true`로 바꾼다.

현재 [synerex_rtk.py](../core/device/synerex_rtk.py)는 `$--THS` 문장(GPTHS/GNTHS)의 heading을 파싱한다. 반면 RMC/VTG의 방향 필드는 이동 방향인 course over ground이므로, 듀얼 안테나 정지 헤딩의 검증 기준으로 사용하지 않는다. 현재 구현은 RMC/VTG 값도 같은 heading 변수에 기록하므로, 수신 문장 순서에 따라 진짜 듀얼 안테나 헤딩을 course over ground 값이 덮어쓸 수 있다. APROS에서 신뢰성 있게 듀얼 안테나 헤딩을 사용하려면 GPTHS/GNTHS를 활성화하는 것과 함께 파서에서 THS 값을 우선 보존하거나, SYN-3100에 대해 RMC/VTG 방향을 heading으로 사용하지 않도록 처리해야 한다. GPTHS의 상태 필드는 `V`일 때 invalid이며, UM982 예시에서는 유효 출력이 `T`로 표시될 수 있다. 펌웨어가 다른 heading 문장만 출력한다면 파서를 그 문장 형식에 맞춰 보완한다.

APROS 현재 직렬 리더는 위치(GGA/RMC)와 헤딩 문장을 수신해 텔레메트리로 발행한다. RTK 위치 상태가 `RTK Fixed`인지와 heading 유효 여부는 별도로 확인한다. GNSS heading이 나오더라도 위치가 RTK FIX가 아닐 수 있고, 반대 경우도 가능하다.

## 7. 문제 해결 체크

| 증상 | 먼저 확인할 항목 |
|---|---|
| 한쪽 안테나만 추적하거나 헤딩이 없음 | ANT1/ANT2 연결, 동축 케이블, 안테나 바이어스, 두 안테나 하늘 시야 |
| 헤딩이 0 또는 고정값으로만 보임 | GPTHS/GNTHS 출력 활성화와 APROS 직렬 포트/baud rate, 문장의 유효 상태 |
| 헤딩이 차량 방향과 180° 다름 | ANT1과 ANT2 위치/포트 라벨, 장착 전후 방향 |
| 헤딩이 차량 종축과 일정 각도 어긋남 | 기준선 설치 각도, 장착 오프셋 측정 및 `CONFIG HEADING OFFSET` |
| 헤딩 편차가 크거나 FIX가 느림 | 기준선 고정 상태, 두 안테나 간격, 하늘 시야/멀티패스, RTCM 수신 상태 |
| RTK 위치가 FIX가 아님 | RTCM v3.x 입력, NTRIP 접속, correction age 및 위성 추적 상태 |
